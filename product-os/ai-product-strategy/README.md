# AI Product Strategy

The reasoning layer between company context and execution: what to build, in
what order, what not to build, and why the shape wins.

## Expected artifacts (built on direction)

- `product-vision.md` — the multi-horizon arc: full observability → agentic SRE
  → cloud-native security (CDR / VM / CSPM) → AI observability & security for the
  AI stack
- `roadmap-sequencing.md` — horizon ordering, gating criteria between horizons,
  what each horizon must prove before the next starts
- `bets-and-non-goals.md` — explicit bets and explicit non-goals (on-prem,
  Azure/GCP-first, day-one full autonomy, staffed-SOC buyers)
- `moat-thesis.md` — unified ops + security data; the one-sensor eBPF advantage
  (observability and security from the same kernel stream —
  see [`../context-hub/ebpf-signal-thesis.md`](../context-hub/ebpf-signal-thesis.md))
- `category-strategy.md` — "unified observability and security operations" as a
  category; analyst-relations narrative
- `competitive-strategy.md` — how the wedge (unified team + unified budget) holds
  against each of the fixed 7 competitors
- `build-vs-buy.md` — per capability
