HNSW vs IVF-Flat: Choosing the Right Vector Index for Similarity Search

Prep notes for the vector-index decision behind ai-engine's memory layer (see AI-platform-Architecture/ai-platform-architecture.md's "RAG for Knowledge Retrieval" line, and the not-yet-started Phase 7d AI Chatbot / RAG item in the root README.md). Covers the two workhorse ANN index families — graph-based (HNSW) and cluster-based (IVF) — plus IVF's compressed sibling, IVF-PQ.

Sources: see Sources at the bottom.

Why an index at all?

Exact nearest-neighbor search over embeddings means comparing a query vector against every stored vector — fine for a few thousand rows, unworkable past a few million. Approximate Nearest Neighbor (ANN) indexes trade a small amount of recall for large speedups by restricting the search to a promising subset of the data. The two dominant strategies structure that subset differently:

HNSW — build a navigable graph, walk it IVF-Flat — cluster first, search only the nearest clusters IVF-PQ — IVF's clustering + compressed vectors

Graph-based HNSW

Hierarchical Navigable Small World graphs build a multi-layer graph where every vector is a node connected to nearby nodes. Higher layers form a coarse, sparse representation of the space; lower layers capture fine-grained relationships, with layer 0 containing every point.

Query algorithm

  1. Start at the designated entry point, in the top layer.
  2. Greedily move to the neighboring node closest to the query.
  3. When no neighbor improves on the current node, descend one layer.
  4. Repeat until layer 0, where the search returns the final nearest neighbors found.

Parameters

ParameterControls
MGraph connectivity — how many edges each node keeps. Higher M → better recall, more memory.
efConstructionSearch breadth used while building the graph. Higher → better graph quality, slower build.
efSearchSearch breadth used at query time. Higher → better recall, slower query.
Strengths
  • Very high recall, often close to brute-force accuracy
  • Real-time insertions and deletions — no retraining pass needed
  • Handles dynamic, continuously evolving datasets well
Limitations
  • Higher memory footprint — the graph edges themselves cost space
  • Slower index construction than cluster-based approaches
  • Three interacting parameters to tune (M, efConstruction, efSearch)

Cluster-based IVF-Flat

Inverted File with Flat storage clusters the dataset with k-means up front. Each cluster centroid gets an inverted list of the vectors assigned to it — "flat" because vectors inside a list are stored in full precision, unquantized.

Query algorithm

  1. Compare the query vector against every cluster centroid.
  2. Select the nprobe closest centroids.
  3. Exhaustively search only the vectors inside those selected clusters.

Parameters

ParameterControls
nlistNumber of clusters created during the k-means training phase.
nprobeNumber of clusters actually searched per query — the main speed/recall dial.
Strengths
  • Fast queries once clusters and nprobe are tuned
  • Moderate memory use — no graph edges, no compression overhead
  • Scales well to very large, largely-static datasets
Limitations
  • Needs an upfront k-means training pass over representative data
  • Inserting/deleting after training is inefficient — clusters go stale
  • Recall is directly gated by nprobe: too low and true neighbors sitting in unsearched clusters get missed

Compressed IVF IVF-PQ

IVF-PQ keeps IVF-Flat's clustering step and adds Product Quantization (PQ) to shrink how much space each vector takes — trading some precision for a large memory reduction, which matters once the collection is large enough that storing every vector at full precision gets expensive.

Product Quantization: compressing a vector in four stages

Compression, concretely: a 128-dimensional vector at 32-bit floats is 4,096 bits. With m = 64 sub-vectors and nbits = 8 bits per centroid index, it compresses to 64 × 8 = 512 bits — an 8× reduction.

Search: two stages

Parameters

ParameterPurposeTypical range
nlistCluster count (IVF step)[1, 65536]; recommended [32, 4096]
nprobeClusters searched per query[1, nlist] — balances speed vs. recall
mNumber of sub-vectors (must divide the vector's dimension)recommended [D/8, D]
nbitsBits per centroid index — larger means less compression[1, 24]; recommended [1, 16]

Versus IVF-Flat, IVF-PQ needs significantly less memory through compression, at the cost of some precision from quantization. Higher m and nbits improve accuracy but add compute; higher nprobe improves recall at a latency cost — the same three-way tension as everywhere else in ANN search.

Decision guide

Hybrid option — IVF-HNSW: some engines (FAISS, Milvus) combine both: IVF partitions the data into clusters, then HNSW does the fine-grained search within each cluster — scalability from IVF, strong recall from HNSW.
Neither source claims a universal winner: benchmark both approaches on your own data and measure recall, latency, and memory before deciding.
